# 5–8 分钟演示与验收脚本

> 这是一个隔离夹具演示脚本，不是学生真实成果报告。演示文本由本文件预设，不是对作者/许可的核验，不能把屏幕上的示例回答、计数或截图归因于真实学生。真实账号、真实历史、真实麦克风和远程写入不在本脚本中。

## 演示前的安全检查（演示者自检）

- 使用独立浏览器上下文/测试账号，确认不是已有认证 profile；不开启 live Supabase、attempt/annotation 自动同步，不运行 seed 或迁移。
- 准备本文件预设的演示文本夹具：
  - 首稿：`Students should study together because it is useful.`
  - 目标：`把建议写成含时间和具体动作的一句。`
  - 二稿：`Before Friday's meeting, each student can bring one question and explain where they got stuck.`
- 明确告诉观看者：这是**演示文本**，不是学生真实成果；本机录音、版权资源和 AI 评分不参与。
- 记下当次 build/测试状态；不在演示时声称 CI、RLS、迁移或部署已通过。

## 5–8 分钟流程

### 0:00–0:45 说明边界

说：

> “我会演示一个隔离夹具中的练习闭环。它展示目标是怎样从首稿进入下一稿；屏幕上的文字是预设演示文本，不是学生的真实成果。我们今天不验证真人录音、云端恢复、版权授权或 AI 评分。”

指出当前页面、考试和 unit 标题。若目录来自本地样例，直接说“这是本地目录”；不要说“远程数据库已经部署”。

### 0:45–2:00 首稿

1. 打开 CET4 写作样例。
2. 将演示首稿放入回答框，不填姓名、邮箱或个人经历。
3. 指出字数提示是长度辅助，不是质量评分。
4. 点击检查/提交一次，等待明确反馈。

验收观察：

- 文本和换行仍在输入框/结果中。
- 主观写作不显示虚构的自动官方分数。
- 如果失败提示未保存，停止链路，复制文本，不继续制造记录。

### 2:00–3:00 首稿复盘

在复盘 notes 写：`useful 没有说明谁在什么时候做什么。`设置一个目标：`把建议写成含时间和具体动作的一句。`保存后读页面反馈。

验收观察：

- 复盘字段属于同一首稿，而不是产生一条伪造的“新练习”。
- 原始回答和耗时不因编辑 notes 改变。
- 若界面只写入当前 draft、没有明确 history 成功提示，标为“待验收”，不要说已保存。

### 3:00–5:00 目标再练

**本机链路已通过离线测试和隔离组件浏览器检查；正式演示入口仍需课前复测。**从当前 Session 的目标入口开始新稿，不直接打开一个猜测的 URL，不复制覆盖已有未提交 draft。本机最新离线检查与构建结果见项目 [README](../README.md)；真实账号与正式入口仍需另行验收。

1. 看到目标副本和覆盖确认后继续。
2. 让新稿从首稿文本开始（当前规则按 skill 决定），只把建议改为：`Before Friday's meeting, each student can bring one question and explain where they got stuck.`
3. 点击“检查并保存本次练习”，等待历史与复盘显示已保存。
4. 在结果区的“本次复盘（可选）”填一句修改说明：`加入 Friday、each student 和 bring one question，让行动更具体。`等待复盘再次显示已保存，再进入详情。

验收观察：

- 新稿有不同且稳定的 attempt 身份。
- 新稿带 `parentAttemptId`，而不是按相邻时间猜父稿。
- 首稿仍可打开，未被二稿覆盖；完整文字没有被 400 字符策略截断。
- 取消覆盖或保存失败时，原稿和当前输入仍保留。

若任一项没有证据，就在演示中说“目标链路待验收”，改用纸面并排展示两段文本，不要把 UI 结果算作通过。

### 5:00–6:30 详情对照

打开首稿/二稿详情，指出：目标、父子关系、原始回答、二稿回答和修改说明。父稿缺失或已移出 120 条历史保留范围时，展示真实提示；不把附近的一条记录冒充父稿。

验收观察：

- 详情读 ID 时能处理原始、编码和非法编码，不循环解码。
- loading、读取失败、真正为空和不存在记录显示不同状态。
- 详情中的录音说明仍是“临时本机内存”，不显示云端恢复承诺。

### 6:30–8:00 收束

说：

> “这个演示只证明隔离夹具里可以尝试一条操作链。它不证明学生成绩提升、版权许可、真人音频、RLS/事务、跨设备恢复或 AI 评分。课堂试用请填写匿名反馈，问题包括保存是否清楚、修改目标是否可执行、失败时能否保留文字。”

结束后关闭测试服务/上下文，检查没有把截图、profile、报告或夹具数据放进公开 artifact。

## 账号切换隔离验收（需授权的真实账号/浏览器操作）

以下不是本轮离线测试证据；只有在获得管理员授权、隔离浏览器和真实 Auth/RLS 环境后执行。另请注意：客户端 boundary 的隐藏/卸载不能证明服务端 RSC/Flight 响应未携带服务端先读取的私有数据；如将此项纳入正式隐私验收，应单独检查网络响应和“验证后取数”的实现：

1. 在用户 A 的标签页建立一条带草稿/历史/标注的记录，确认其属于 A 的本机 namespace。
2. 在另一标签页退出 A 并登录用户 B；观察仍打开的 A 页面应立即隐藏私有内容并进入重新验证/登录流程，不接受 B 的身份继续渲染旧页面。
3. 复核旧 A 页面不能读取或修改 B 的本机 namespace；A 的原记录不应被删除或自动上传给 B。
4. 刷新或重新进入 B 页面后，只能看到 B 的数据；在独立 A 会话中确认 A 的数据仍保留。
5. 记录真实 Auth/RLS、跨标签页时序、失败路径和是否有无法取消的在途请求；本地 Node harness 不能替代这一步。
